2.1 hRound 5 - train side: form the OPD advantage inside the training forward
The actor's forward-only log-prob pass existed only to give the OPD advantage the
student's log-probs of the current weights - which the training forward computes anyway.
When both KL terms are dead and the advantages are not whitened the two are the same
tensors, so the loss can apply the reverse KL to what it just computed
(SLIME_OPD_INLINE_ADVANTAGE=1).

First attempt was wrong: the inline advantage carried the forward's graph, so the policy
gradient picked up an extra d(advantage)/d(log_probs) term (grad_norm 1.088 vs the
reference's 0.9966). The reference's advantage comes from a graph-free forward, so the
substitution has to detach it; with that, step 0's loss, pg_loss, entropy_loss,
pg_clipfrac, ppo_kl and train_rollout_logprob_abs_diff are bitwise identical to the
reference's and grad_norm is 0.99655 vs 0.99666 (d = 1.2e-4, tolerance 1.65e-3).

time --side train with both switches: windows 46.320 / 48.323 / 44.952 (mean 46.532) vs
the frozen 73.779 / 72.317 / 72.521 -> side speedup 1.5675 (was 1.298 without it).
The log-prob timer disappears from the run's own timer log.

Combined projection: 1 / (1 - (0.4926*0.2109 + 0.4738*0.3620)) = 1.38.

Teacher attempt (logged as no-gain): OPD_TEACHER_SERVER_ARGS=--chunked-prefill-size 8192
gives teacher windows 17.579/17.860/17.358 vs the frozen 18.284/18.251/17.861, side
speedup 1.0303 - 0.3% of the step, and it would trade the teacher's currently

0.4 hRound 3 - train-side profile and the dead reference pass
profile --side train timer breakdown of one warm train step (72.9 s total):
- ref_log_probs (reference model's forward-only log-prob pass): 10.8 s
- log_probs (actor's forward-only log-prob pass): 9.9 s
- actor_train (fwd + full-recompute + bwd): 45.9 s
- sleep/wake of the colocated Megatron: 5.7 s
The recipe passes --use-kl-loss --kl-loss-coef 0.00 and --kl-coef defaults to 0, so
the reference model's log-probs feed only terms multiplied by zero. Change: the actor
skips that forward pass when both KL coefficients are zero, and policy_loss_function
follows the data's presence. Tier N0 (the loss and its gradient are unchanged bitwise:
loss + 0 * kl_loss == loss).

Also added SLIME_RECOMPUTE_GRANULARITY (Megatron training/arguments.py): an opt-in
override of the activation-recompute granularity. Full recompute costs one extra
forward per layer; the colocated engines release their pools during training, so there
is device headroom to keep the activations instead.

Bug found and fixed while timing this: DataIterator.get_next fills a requested key
with None when the rollout data does not carry it, so "ref_log_probs" in batch is
True with a None value. The first version of the loss guard used in batch and
crashed with TypeError: cat(): argument 'tensors' ... not NoneType. The guard now
tests batch.get("ref_log_probs") is not None, and kl_loss is reported only when it
was computed.
