Root cause found (torch source, torch/cuda/graphs.py:240-252):

Root cause: add_latent repeats the 0-dim CUDA dt/timestep tensors once per latent
token into packed_input['packed_timesteps'], loss_info['dts'],
loss_info['packed_timesteps_for_loss']; _convert_to_tensors then rebuilds those lists
with torch.tensor(list, dtype=float32, device=...), which reads every element back with a
blocking D2H. pack_batch's CFG filter also compares each per-sample timestep tensor against
the bounds (2 syncs per element).

Change (commit 1d87f41, switch OPT_PACK_HOST_FLOATS, off by default, N0):
add_latent converts dt/timestep to host floats once per SDE step; pack_batch hoists
one .tolist() of the shared per-sample timestep tensor for the CFG filter.
Bitwise argument: float32→float64→float32 round-trip is lossless (final torch.tensor
identical; verified with an int32-view equality unit test). The CFG comparison keeps the
same booleans: bounds are 0.4/1.0, and no float32 grid point lies between float64(0.4) and
float32(0.4) (window < 1 ulp), 1.0 is exact — so host float64 comparison ≡ GPU float32
