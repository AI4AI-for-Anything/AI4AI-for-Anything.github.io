1.0 hFinding (round 2): the Qwen3.5 linear-attention layers run replicated
- slime_plugins/models/qwen3_5.py builds the attention of every layer on HuggingfaceAttention; the default
  --qwen-gdn-implementation is replicated (the recipe does not set it). The replicated GDN module keeps full weights
  on every rank: the sequence hidden states are all-gathered over TP (SP) and CP, so the 24 linear-attention layers run
  the whole 8k-token sample on each of the 4 GPUs (~4x the ideal GDN work per GPU). That explains the low train MFU
  (~26%: ~72 GFLOP/token x 8.3k tokens per microbatch / 0.7 s).
- The alternative --qwen-gdn-implementation megatron (qwen3_5_native.py, Megatron's TP/CP GatedDeltaNet) has
  different parameter names and sharded shapes (in_proj combined, partition_sections). The judge's record gate compares
  the names and shapes of every bf16 parameter, fp32 master weight and Adam moment exactly, so this path cannot pass
  the structure gate without a new checkpoint layout. Not pursued.
- Possible in-layout lever (not done): shard the replicated GDN computation over TP/CP while keeping the full parameter
  shapes (needs gradient all-reduce for replicated weights). Large change; keep as the expensive option.
