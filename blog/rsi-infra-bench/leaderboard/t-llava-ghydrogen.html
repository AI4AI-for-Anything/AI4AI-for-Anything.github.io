0.7 hRound 2 — DeepSpeed ZeRO Stage (ZeRO-2 + 5e8 Buckets + ZeRO-3 RoPE Compatibility)
- Window: 2026-11-20T01:35:00Z – 2026-11-20T02:03:24Z
- Root-Cause Diagnosis (diag_zero2_vs_zero3.py, diag_diff_layer.py, diag_llama_diff.py):
  - Initial zero2.json run hit 2679.9 ms (1.0376x) but failed Gate 1's step 1 logged_loss <= 0.005 check (1.3758 vs ref 1.3839, rel diff 0.00585).
  - Layer-by-layer isolation proved 100% of parameters matched bitwise (sha256 identical), and the step-1 forward difference came from two ZeRO-3 side effects:
    1. zero.Init() initializes LlamaRotaryEmbedding.cos_cached / sin_cached with t = torch.arange(..., dtype=torch.bfloat16).float() on CUDA (inv_freq in CUDA fp32), quantizing positions >256 (257 -> 256, 513 -> 512), whereas standard CPU/CUDA ZeRO-2 keeps t in fp32 (-0.0054 loss shift).
    2. DeepSpeed ZeRO-3 LinearFunctionForZeroStage3 uses input.matmul(weight.t()); output += bias instead of PyTorch F.linear's fused cuBLASLt bias epilogue (~0.0005 loss shift).
  - Reproducing ZeRO-3's exact cos_cached/sin_cached initialization once at model load (LLAVA_OPT_Z3_ROPE=1, 0 diffs across all 524,288 entries, <1 ms startup cost, zero runtime cost) dropped logged_loss_first_step_rel_diff from 0.00585 to 7e-05 (1.3838 vs 1.3839).
