3.8 hRound 7 — FIRST full gate-3 check exposes a DenseAdam bug; fixed (start ~03:45)
Ran the first FULL check (gates 0-3, seed 1) on the round-6 state: INCORRECT. Exact items (3000 steps)
passed, but every gate-3 endpoint was far beyond 3σ: PSNR −0.289 (−7.4σ), SSIM −20.6σ, LPIPS +40σ,
log_count +4.8σ. Quick checks alone had masked a real training divergence.

Isolation (full checks, config-only, tree unchanged):
- cfg A = N0 + GS_FUSED_ADAM only (DENSE_ADAM=0, FUSED_ACT=0): PASS, N1, 1.3646x (PSNR −0.013). Sound base.
- cfg B = A + DENSE_ADAM=1 (FUSED_ACT=0): INCORRECT (PSNR −0.321). ⇒ DenseAdam is the culprit.

Root cause: denseAdamCUDA second-moment update was vv += omb2*(g*g) — it ADDS (1−β2)·g² but never
DECAYS vv by β2. Correct Adam: vv = β2·vv + (1−β2)·g² = vv + (1−β2)·(g²−vv). Without decay exp_avg_sq grows
~linearly, denom inflates, updates shrink → underfit + over-densify (matches PSNR↓ + count↑). A single-step
microbench from zero state cannot catch it (both forms equal omb2·g² when vv=0) — that is why round 3's
kernel-level check and the 3000-step exact-items check passed.

Fix: float4 + scalar tails now vv += omb2*(g*g − vv). Multi-step (200) microbench vs torch.Adam over 8
shapes incl. odd tails: OLD ext MISMATCH (param 1.6e-3, exp_avg_sq 3e-2); FIXED ext MATCH (param 1.4e-6,
exp_avg_sq 3.5e-6 — float rounding). Ext /tmp/gs-ext/7a508c2e965b4e1cbd5b07c9.

Secured passing state meanwhile: /submission/switches.json set to cfg A (1.3646x) until the fix was verified.
Full check with fixed DenseAdam + FUSED_ACT (cfg_full, /tmp/r7/chkFull): PASS, tier N1, speedup 1.5544
(candidate 211.929 s). Endpoints all within 3σ: PSNR −0.036, SSIM +0.00003, LPIPS −0.00012, log_count +0.0021.
⇒ FUSED_ACT was sound; the sole bug was the DenseAdam missing β2 decay. Fix recovered the full speedup.

Idea: halve sampled_T/ar round-trip traffic by sampling every 64 splats instead of 32. Feasibility probe
(/tmp/r12/tree, forward.cu sampled writes guarded by GS_NO_SAMPLE_WRITE macro, setup.py -D; forward-only

BLOCKER: the backward PerGaussianRenderCUDA is a DIAGONAL warp-scan pipeline — thread t at loop iter i
handles splat t, pixel i−t; per-pixel T/ar propagates via shfl_up across iterations (thread t gets thread
t−1's state from iter i−1, same pixel). 1 warp is fundamentally 32 splats. A 2-splat/thread (64-bucket)

risk/effort. ABANDONED — probe copy only (/tmp/r12), submission untouched (f469b9b). Design documented for
