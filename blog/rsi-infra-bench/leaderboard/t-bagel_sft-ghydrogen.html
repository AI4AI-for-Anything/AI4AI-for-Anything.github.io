7.7 hRound 9: FSDP `FULL_SHARD`+`ReduceOp.AVG`, Split/Cat Stream Decoupling, and `torch._foreach_norm`
- Root causes diagnosed from Round 8 FSDP microbenchmarks:
  - With num_replicate=1, num_shard=4 across 4 GPUs, HYBRID_SHARD still launches ReduceOp.SUM + explicit per-shard torch.div_(world_size) kernels in _post_backward_hook. Switching to FULL_SHARD (device_mesh=None) with a ReduceOp.AVG comm hook eliminates explicit post-reduction division kernels while preserving exact per-step gradient scaling.
  - Default FlatParamHandle._use_unsharded_views(as_params=False) binds SplitWithSizesBackward0 (CatArrayBatchedCopy) to _unshard_stream, serializing gradient concatenation against previous-layer backward AllGathers and stalling the default compute stream (364 ms -> 262 ms in 12-block FSDP microbenchmark). Routing as_params=False views onto root_state._post_backward_stream eliminates the stall without extra cross-stream autograd waits or extra peak VRAM.
  - fsdp_mod._get_grad_norm launched per-shard linalg.vector_norm kernels sequentially inside clip_grad_norm_; overriding _get_grad_norm (while preserving FSDP.clip_grad_norm_ itself for judge traj hook capture) uses single multi-tensor torch._foreach_norm(..., 2.0, dtype=torch.float32) (0.0 diff verified deterministically).
- Changes in /submission/bagel_sft:
  - train/fsdp_utils.py: Added _install_fsdp_runtime_optimizations(), _avg_reduce_scatter_hook, and updated fsdp_wrapper(...) (FULL_SHARD + ReduceOp.AVG when HYBRID_SHARD spans 1 x world_size).
