5.3 hRound 14 (00:30-00:45): fused AdamW on the fp32 master partitions
DeepSpeed's BF16_Optimizer re-points the client optimizer at one flat fp32 partition
per parameter group, then calls its step(), so a custom optimizer can replace
torch's ~5-pass foreach AdamW with one pass. Implemented
llava/train/fused_adam.py: a Triton kernel that reads p/g/m/v and writes p/m/v in
one pass, with torch's AdamW formula (decoupled weight decay first, beta1/beta2 bias
correction, eps inside the denominator); the optimizer keeps the standard
exp_avg/exp_avg_sq/step state (fp32) and the standard betas/eps/
weight_decay param-group keys, so DeepSpeed's safe_get_full_optimizer_state
and the judge's hyperparameter/state checks see the usual interface.
Hooked in via LLaVATrainer.get_optimizer_cls_and_kwargs (LLAVA_FUSED_ADAM=1).
- time /tmp/r15/time: 1251.9 ms/step, speedup 2.2248 (+4% over 2.139); first
  five logged losses bit-identical to the foreach baseline, later ones differ by
  ~0.3% (update rounding, N1). Timing peak unchanged at 126.0 GiB.

With packing the step time is set by the rank holding the most tokens, so the
sampler's word-count key was replaced by the real token length (allowed: the key may
be replaced by token length, the megabatch membership still comes from randperm, so
the probe's per-step multiset is unchanged).  Verified from the loader reference:

the measured step time was 1262.7 vs 1251.9 ms (noise, wrong direction).  Reverted
(also avoids paying a repartition for a sub-noise gain).
6.1 hRound 17 (01:05-01:20): no-fill packed embeddings
Under packing the padded rows of the multimodal embedding batch are never read (the
pack gathers the cu_seqlens slices), so their zero-fill and the per-sample
cat(embed, zeros)+stack are waste. LLAVA_PACK_NO_FILL allocates the padded batch
once with torch.empty and copies only the real rows (right padding, guarded on
LLAVA_PACK). Numerically exact (the pad values are never consumed; first loss
