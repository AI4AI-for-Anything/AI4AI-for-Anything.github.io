5.3 hRound 12 — lazy SH Adam (18:00–18:50)
Hotspot: adamFusedCUDA 0.80 ms/iter (23%), at the HBM floor because it updates all 59 floats of every Gaussian (2.3 GB/iter) although the SH
parameters (48 of 59 floats) are only observed for Gaussians that are rendered (~30%) and the others have a gradient of exactly zero.
Change (GS_OPT_LAZYSH=1, needs CUSTOM_ADAM/RAWRENDER/VISADAM/FASTDENSIFY): Adam for xyz/opacity/scaling/rotation stays dense (needed every
step for the culling); the SH update is applied lazily: per Gaussian applied[row] (steps incorporated) and gs[row] (step whose gradient is in a
persistent buffer written by the backward preprocess). After the tile count the rendered Gaussians (tiles_touched > 0) are brought up to date by
lazyShRowsCUDA (one warp per 32 rows, two Gaussians at a time over half-warps; first the pending gradient step with the dense update formula,
then the k missed zero-gradient steps in closed form: m*b1^r, sqrt(v)*b2^(r/2), p -= ss*m*b1^r/(sqrt(v)*b2^(r/2)/bc2+eps), float32-rounding
equivalent to the sequential update), then shColorCUDA computes their colors. Densification flushes all rows (and skips the SH step like the
dense optimizer does when the parameters are replaced), the last optimizer step (step count == iterations-1) flushes before the judge's hook
reads the parameters, state_dict/save_ply flush too. Step tables (lr/bc1, sqrt(bc2)) are built with the dense update's Python formulas.

sequential catch-up was bitwise identical), lazy_bench.py (kernel time). First (flat, per-element) catch-up kernel: 1.3 ms -> time 112.6 s

9.3 hRound 20 — deterministic training (22:00–22:42)
Goal: remove the run-to-run noise of gate 3 (~6% fail risk estimated for a single sample): make the whole training bitwise reproducible, so that the d measured in a
check is exactly the d of the final evaluation.
Sources of nondeterminism found: (1) the float atomics of the render backward (order of the additions) -> 64-bit fixed-point accumulators (fxAdd: round(v * 2^46)
(conic: 2^36) added with an integer atomicAdd; converted back in the backward preprocess; dL/dmean2D is written as float by the preprocess for the densification
statistics); (2) imgState.max_contrib of the forward render kernel: cub::BlockReduce<uint32_t, BLOCK_SIZE> is used with a two-dimensional thread block, so its linear
thread index is threadIdx.x only, 8 threads of every column race on the same slot and the slots of the other warps are never written (uninitialised shared memory): the
per-tile maximum of the last contributors, which bounds the buckets of the backward, depended on stale shared memory. (The REFERENCE rasterizer has the same code,
forward.cu:427, with 16x16 blocks.) Now a warp-shuffle max + one shared slot per warp = the exact maximum.
