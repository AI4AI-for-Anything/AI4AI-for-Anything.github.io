0.1 hRound 1 — profile the unchanged reference, then remove redundant train work + rollout payload
Start ~22:22. Profiles (reference tree, unchanged) launched detached:
/tmp/r1/run_profiles.sh -> /tmp/r1/profiles.log (train profile then rollout profile).

Change A (train side, switch SLIME_OPT_SKIP_ZERO_KL_REF, default off):
the recipe passes --use-kl-loss --kl-loss-coef 0.00, which makes with_ref=True and runs a full
extra reference-model forward (~12.2 s/step) whose only consumers (KL advantage penalty, KL loss
term) both have coefficient 0. Skip it, and skip the KL loss term in loss.py; advantages already
fall back to zero KL for kl_coef==0. Parameters are unaffected (the ref pass is forward-only).
Change B (train side, switch SLIME_OPT_NO_RECOMPUTE, default off):
--recompute-granularity full --recompute-method uniform --recompute-num-layers 1 recomputes all
32 layers during backward; free GPU memory during training is ~105 GB so drop it. Recomputation
re-runs the same forward, so the arithmetic is unchanged (peak activation memory rises).
Change C (rollout side): sglang tokenizer_manager puts the nested output_top_logprobs
(8192 x 128 tuples per sample, ~2x the compact payload) into every non-streaming response in
addition to the base64 output_topk_* arrays that slime actually consumes. Drop the nested field
for non-streaming compact responses (streaming/text-logprob clients unchanged). No data change.
Change D (rollout side): parse the response with orjson instead of stdlib json.

7.8 hRound 7 — TP communication overlap investigation (rejected: incompatible with dynamic batching)
The train profile showed 33% of kernel time in sequence-parallel NCCL collectives, so the next
target was Megatron/TransformerEngine userbuffer (UB) overlap of the all-gather / reduce-scatter.
- Attempt 1 (SLIME_OPT_TP_COMM_OVERLAP=1 alone): TE's CommOverlapHelper asserts the
  intra-domain group's backend type == the comm backend. slime wraps every torch.distributed group
  in ReloadableProcessGroup (a plain ProcessGroup with the real one inside), so the backend
  reads as undefined. Failed at actor init.
- Added SLIME_OPT_NO_RELOADABLE_GROUPS=1: skips only monkey_patch_torch_dist() (keeping
  offload_train=True so the torch_memory_saver setup the actor needs stays intact; the
  destroy/rebuild calls are already skipped by the resident path). Now TE initialises its
  userbuffers and the run gets into training, but fails at the first overlapped GEMM:
  `comm_gemm_overlap.cpp:455 copy_into_buffer: Assertion failed: _ubufs[_tp_id].numel() ==
  input_size`. The UB buffers are sized once from
  (seq_length * micro_batch_size) // cp_size, while this recipe uses dynamic batching with a
  per-microbatch token count (M = 4096-4224 after CP2 slicing/padding). TE requires the copied
  input to match the buffer *exactly*, so UB overlap cannot be used with variable-length
  microbatches without reshaping every microbatch to one fixed M (which would change the
  batching/data order). Rejected; both switches stay off.

Also examined and rejected for this round: fla's fused gate (use_gate_in_kernel) in the GDN
plugin would remove ~3-4 eager elementwise kernels per layer (gradients for A_log/dt_bias are
supported in the fla backward), worth well under 1% of the step; and fla's native GVA
(HV > H) only removes the q/k repeat copy (~0.03 s/step) because the qk products scale with
HV either way.
