8.7 hRound 22 (13:32-13:41): costed out the remaining bitwise levers; final timing confirmation
With the N1 route closed (see round 21), this round worked through every remaining way to get faster *while staying
bitwise identical* -- the only tier that skips the chaotic trajectory gate:

| idea | why it is not usable |
|---|---|
| checkpoint only the RMSNorm's fp32 intermediates to free memory for more AC layers (~10 GB of fp32 h are saved for the backward across 12 layers) | impossible under FSDP: with use_orig_params=False the module's parameters are bare views into the unsharded flat param, which FSDP frees on the post-forward reshard; a recompute inside an un-checkpointed layer would read dangling memory.  That is exactly why FSDP's own layer-level AC re-gathers on recompute. |
| BAGEL_AC_SKIP_DECODER=13 | +1.25% for ~4 GiB; at 12 layers the record peak is already 110.2 GiB allocated / 111.9 timing (~130 GB of the 140.4 GB card).  Any non-zero OOM probability multiplies the *whole* score, so the expected value is negative (1.138 x 0.97 < 1.126). |
| a bitwise Triton RMSNorm (fused fp32 chain) | would need to reproduce PyTorch's reduce_kernel fp32 tree bit for bit in both forward and backward across every real (n, D); the payoff is ~4-6%, the success probability is low and a single 1-ulp miss drops the tree to N1 and the coin flip. |
| fused torch.nn.functional.rms_norm | measured 1 bf16 ulp off the chain (the chain casts to bf16 before the weight multiply, the fused op after) -> N1. |
| CUDA graphs | graphs are shape-specialised and the packed sequence length changes every step; padding to fixed shapes changes the arithmetic. |
| norm-level fusions / new_empty / MoT gather+norm+scatter | each measured at <=0.3% in earlier rounds. |
