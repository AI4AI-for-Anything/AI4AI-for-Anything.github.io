```
    int local_x = thread_index().x + 5;          // 5..36

    ...                                          //     32-wide row
```

do_separable_conv_y reads column indices 5..36 out of a buffer whose row stride is
32, so it reads across row boundaries (harmless to the address, wrong to the value)
and, on the last rows, runs 4 floats past the end of buf3 -- the 0x5020 the
sanitizer reported (plus block/alignment padding).

This is part of the reference's own loss. The frozen seed-1 trajectory was
produced by a fused-ssim that reads those columns, so "computing the same thing"
means preserving this behaviour exactly. Repairing the row width would change the
SSIM value, hence the loss, hence the whole trajectory -- a semantic change, and one
that gate 3 would reject.

That settles the SH write staging for good: adopting its ~0.8 % would require *both*
restructuring the backward preprocess *and* changing a loss kernel whose current
behaviour is the reference. 0b85795 stays.

blaming a new patch for such a fault.
