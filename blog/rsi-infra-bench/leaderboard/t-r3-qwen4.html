- Hotspot: the same one the profile pointed at. After rounds 1-2 the decode step still launches ~250 kernels whose

- Change: capture embed_tokens -> 28 decoder layers -> lm_head into a torch.cuda.CUDAGraph and replay it.
  Replay launches exactly the kernels the eager path launched, in the same order, with the same arguments, so the
  arithmetic is unchanged (N0 by construction). Deliberate design points:
  - Sampling, softmax and the autoregressive bookkeeping stay eager: they draw from the rollout generator,
    and a captured RNG op would replay a frozen philox offset.
  - The KV cache is not an input buffer: it is a persistent tensor the captured kernels read and write at run
    time, so the advancing seq_lens propagates through replay without re-capture.
  - Static input buffers: tokens, position ids, active-sequence indices, and a constant query_lens of ones.
  - One graph per active-batch size (4/3/2/1): the GEMM M dimension changes with it, and a different cuBLAS
    kernel could round differently.
  - fsdp2_rollout_context unshards every FSDP module once and clears the forward hooks, so parameters are
    full and address-stable for the whole rollout and no collective is captured. Graphs are keyed on
    (id(lm), key_cache.data_ptr(), seq_lens.data_ptr(), n) with a weakref to the cache, so a new rollout
    (new StaticKVCache) re-captures and dead entries are purged without pinning ~1 GB of KV memory.
  - Warmup runs the *real* step on the *real* cache 3x on a side stream: it writes the same k/v at the same
    positions the replay will write, so it is idempotent and leaves the cache exactly one step advanced. This
    also allocates the cuBLAS workspace for the capture stream before capture begins.
  - Low-level capture_begin(capture_error_mode="thread_local") / capture_end() instead of the
    torch.cuda.graph context manager, which does gc.collect() + empty_cache() (measured 1.43 s of cudaFree
    per 2 steps) on every capture.
  - _host_len_info is pre-populated for the exact static tensors before capture, so the attention path performs
    no D2H read while capturing; if the memo is unavailable the entry is marked disabled and runs eager.
  - The replay's logits live in the graph's private pool, so they are .clone()d out before returning: evicting a
    graph can then never free memory the caller still holds.
