Change (slime only, switch SLIME_OPD_RESIDENT=1). With the switch the run behaves as if `--no-offload-train
--no-offload-rollout had been given: args.offload_train and args.offload_rollout` are forced off, so Megatron is
never put to sleep or woken and the engines never release or resume memory; the same tensors, kernels and
communicators stay alive. The weight updater then reads the live Megatron parameters (the CPU backup is skipped), and

loaded when offload_train is on). To make room for the resident training model the engines' static memory fraction

concurrent requests while a rollout puts at most 32 on an engine (KV pool 1.21 M -> 705k tokens, mamba cache 696 ->
401 slots = 80 running requests per engine; a rollout needs <= 32 requests x ~8.8k tokens = 282k tokens). Files:
slime/utils/arguments.py, slime/backends/megatron_utils/actor.py, slime/backends/megatron_utils/memory.py.
