0.8 hRound 2 (2026-11-19 06:00-...) - attention: varlen kernels instead of per-sample masked SDPA
Change. New modeling/bagel/attention_plan.py derives, from upstream's dense per-sample masks
alone, the block structure that reproduces them, and modeling/bagel/qwen2_navit.py runs the
decoder attention with two flash_attn_varlen_func calls instead of the per-sample loop:

* a row that sees a later column starts a bidirectional block; the block runs to the next row that
  does not, so a block is full or noise and a causal split is never inside one;
* a block is noise iff its columns are seen by its own rows alone (colsum[start] == length),
  which is also exactly when a *trailing* full block behaves like a noise block, so the
  classification is safe;
* the non-noise tokens of a sample, in order, are one causal run; every causal run's keys are its
  sample's non-noise prefix up to the end of the run, so the bottom-right causal alignment makes
  query i see exactly the prefix tokens up to its own position;
* a full block's keys are its sample's non-noise prefix up to the end of the block; a noise
  block's keys are that prefix up to its start followed by the block itself (upstream's noise pass
  hides a noise split's *columns* from everyone else but its own queries keep seeing everything
  before them);
* keys are gathered (prefixes overlap), queries are perm = [causal tokens..., block tokens...]
  and the output is scattered back with inv. GQA needs no repeat - flash-attention takes k/v
  with 4 heads against q with 28.

Behind BAGEL_OPT_VARLEN_ATTN (default 1, =0 restores the per-sample path, kept as
_sample_split_attention). Numerics tier N1 (kernel change; masks, order and shapes are
identical, so gate 2 is no longer bitwise and gates 2b/3 decide).

A second look at the profile (trace, not just the op table) found that the CPU is blocked inside
aten::to / aten::copy_ ~45 times per step, the big ones 35-200 ms each, all of them

vit_max_seqlen (the vision encoder's max_seqlen) and the packed-attention plan are therefore
now resolved by the training loop, while the only work queued is the batch copies and the token
reductions, and passed down through the data dict (which is not part of the batch digest, since
that is taken in SimpleCustomBatch.cuda).  The model still computes them itself when they are
absent.  Tier N0.

8.2 hRound 11 - und-first order for the decoder stack (N0): the second big win
Re-profiling the current tree (/tmp/r27/profile, span 2021 ms/step) attributed the remaining
eager work precisely:

| item | ms/step | calls/step |
|---|---|---|
| index_elementwise_kernel | 152 | 2579 |
| aten::fill_ (inside vectorized_elementwise) | 46 | 1252 |
| aten::div_ / mul / add_ | 61 | ~1900 |
| aten::copy_ (inside unrolled_elementwise) | 63 | 1016 |
| multi_tensor_apply (fused AdamW + EMA) | 53 | 523 |
| CatArrayBatchedCopy | 35 | 102 |

The index kernels and most of the fills come from one pattern: upstream's Qwen2MoTDecoderLayer
and PackedAttentionMoT allocate a zeroed tensor and scatter each expert's result into it by
index, for every projection, both head norms, the output projection and both MLPs, in all 28
layers - and each of those index_put_/index_select ops also allocates a zeroed gradient tensor
in its backward.

Change. The understanding and generation token sets partition the packed sequence, so a single
permutation that puts each of them in a contiguous half turns every one of those gathers and
scatters into a slice. Bagel.forward builds that permutation once per step (and re-expresses the
attention's perm/inv/key permutations in those coordinates), and the whole decoder stack - all
28 layers, the residual stream and the final norm - works in that order: one permutation in, one
out. Behind BAGEL_OPT_UND_FIRST.

Verified bitwise identical to the per-index form on 14 layouts (the real recipe and interleave
layouts, adjacent full blocks, noise-in-the-middle, all-generation, 6 random ones) for a complete
decoder layer, so this is tier N0 - it adds no drift on top of the changes already in the tree.
